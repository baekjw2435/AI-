# 역·격 필승 수순 묶음 (route-book-1)

기초사전 루트 817단어(격언 포함)에서 지금까지 검증된 역·격 수순을 한 엔진과 한 표로 묶었습니다. 사이트 엔진에 넣는 용도입니다. 서버나 데이터베이스는 필요 없고, 정적 파일만 있으면 됩니다.

## 전제

- 사전: 817단어, sha256 `aa37031019f1e2a95b422ffc2f8d8d1b76b03ca88163b03b17af16ff90c79273`
- 규칙: 표준두음법칙, 한 경기 안에서 단어 재사용 금지, 낼 단어가 없으면 패배
- 판정 근거: 수정하지 않은 `verify_v2.py`(sha256 `9019cd1d…`)와 `verify.py`(`b08c2491…`)로 검증한 증명 13개
- 받는 쪽: 상대가 넘긴 음절(역, 격)로 시작해야 하는 사람. 낸 쪽: 그 음절을 넘긴 사람.

## 파일

| 파일 | 내용 |
|---|---|
| `engine.js` | `RouteBook` 엔진. 정준화, 정적 역산, 되받기, 표 조회 |
| `model.json` | 음절, 묶음(같은 시작·끝 음절의 단어 모음), 단어. 번호는 verify_v2.py와 같습니다 |
| `catalog.json` | 시작 음절별 첫 수 분류와 증명 13개의 출처(해시, 노드 수) |
| `tables/b00.bin` ~ `tables/bff.bin` | 승리수 표 256조각. 합계 14,397,209개, 조각당 약 0.55MB |
| `lines/<증명 id>.json` | 엔진이 두는 수순을 상대 세 수까지 펼친 나무 |
| `LINES_KO.md` | 사람이 읽는 수순 요약. 첫 수 분류와 상대 두 수까지의 수순 |
| `index.html` | 단독 실행 데모 페이지 |
| `test_book.js` | Node로 돌리는 무작위 대국 시험 |
| `build/` | 표를 만든 도구. 증명 → 표 추출(`proof2tab.c`), 합치기(`build_book.py`), 분류와 수순 생성 |

## 무엇이 들어 있나

| 시작 | 받는 쪽 첫 수 | 결과 | 엔진이 맡는 쪽 |
|---|---|---|---|
| 역 | 역습 | 받는 쪽 승리 | 받는 쪽 |
| 역 | 역사학·역학, 역방향, 역풍 | 받는 쪽 패배 (반박: 학업, 향토색, 풍류객) | 낸 쪽 |
| 격 | 격증, 격식 | 받는 쪽 승리 | 받는 쪽 |
| 격 | 격랑, 격멸, 격변, 격식적·격정적, 격퇴, 격찬, 격언 | 받는 쪽 패배 (반박: 낭비벽, 멸치젓, 변색, 적갈색, 퇴색, 찬성표, 언약) | 낸 쪽 |

**들어 있지 않은 것**
- 역의 나머지 첫 수(역할·역기능 승리, 역세권·역할극·역병·역순·역전승·역동적 묶음·역행 패배)는 아스트라의 기존 기록입니다. `catalog.json`에 분류만 있고 증명 표는 없습니다.
- 격돌은 보류입니다. 돌격과 왕복 쌍이라 따로 계산해야 합니다.

## 쓰는 법

```js
const model = await (await fetch("model.json")).json();
const catalog = await (await fetch("catalog.json")).json();
RouteBook.init(model, catalog);

const load = (id) => fetch(RouteBook.bucketFile(id)).then((r) => r.arrayBuffer());
// 시작 음절과, 그 음절부터 실제로 둔 단어들. 지금 둘 차례인 쪽의 필승 수를 돌려줍니다.
const mv = await RouteBook.ourMoveAsync("격", ["격찬"], null, load);
// mv = { word: "찬성표", group: 594, how: "증명", alts: [] }
```

- `ourMoveAsync(start, history, initialUsed, loadBucket)`: 필요한 표 조각을 불러온 뒤 수를 돌려줍니다. 한 수에 조각 하나만 씁니다.
- `ourMove(start, history, initialUsed)`: 동기 버전입니다. 필요한 조각이 없으면 `err.needBucket`(조각 번호)를 단 오류를 던집니다.
- 돌려주는 값: `{ word, group, how, alts }` 또는 `null`.
  - `how`가 `"증명"`이면 검증된 증명의 승리수입니다. 계산 없이 상대를 정적으로 지는 자리로 보내는 수도 여기에 들어갑니다.
  - `"정적"`이면 남은 길만으로 승패가 정해진 자리의 수입니다.
  - `"되받기"`이면 상대가 왕복 쌍의 한쪽을 냈을 때 짝으로 받아 직전 국면으로 돌려놓는 수입니다. 필승 수순을 따라온 경우에만 이기는 수입니다.
  - `alts`는 같은 묶음의 다른 단어입니다. 어느 것을 내도 결과가 같습니다.
  - `null`이면 그 국면이 표에 없거나, 둘 차례인 쪽이 지는 국면입니다.
- `legalWords(start, history, initialUsed)`: 지금 낼 수 있는 단어 목록입니다.
- `firstMoves(start)`: `catalog.json`의 첫 수 분류입니다.
- `initialUsed`: 시작 음절을 받기 전에 이미 쓴 단어들입니다. 보통은 `null`입니다. 넣으면 그 국면의 정준형을 표에서 찾습니다. 찾으면 검증된 승리수지만, 이 표는 817단어가 모두 남은 시작 국면에서 뻗은 수순만 담고 있어서 대부분 찾지 못합니다.

**사이트 쪽 주의**
- 사이트의 `game-data.json`과는 번호 체계가 다를 수 있습니다. 엔진과는 단어 문자열로만 주고받으세요.
- 표 조각은 `fetch`로 받는 이진 파일입니다. 서버가 `.bin`을 내려 주기만 하면 되고, 형식(MIME)은 상관없습니다.
- 표 전체는 138MB지만, 한 판에 필요한 조각은 많아야 수십 개입니다(한 수에 0.55MB 한 개).

## 자료 형식

**표 조각 `tables/bXX.bin` (YSK1)**
- 머리: `"YSK1"` 4바이트, 항목 수 n(u32, 리틀엔디언)
- 열쇠: (a, b) 쌍 n개(각 u32). (a, b) 순으로 정렬
- 승리 묶음: n개(각 u16)
- 조각 번호 = a의 최상위 바이트(a >>> 24)

**국면 열쇠**
1. verify_v2.py와 같은 정준화를 합니다. 순서는 왕복 쌍 제거, 자기 연결 짝수 제거, 도달 불가 제거, 정적 역산, 미확정 핵심 추출입니다.
2. 바이트열 [현재 음절 번호 & 255, 현재 음절 번호 >> 8, 묶음별 남은 개수…]를 만듭니다.
3. 이 바이트열에 FNV-1a 32비트를 두 번 계산합니다. a는 앞에서부터(기저 2166136261), b는 뒤에서부터(기저 0x9747b28c)입니다.

증명 노드의 `v`와 `c`(묶음별 개수)에서 같은 방식으로 열쇠를 만들었습니다. 만들 때 별도의 64비트 국면 해시로 확인했고, 서로 다른 국면이 같은 열쇠를 갖는 경우는 0건이었습니다.

**표에서 뺀 수:** 고른 수가 정적으로 지는 자리(증명에서 수가 없는 L 노드)로 가는 W 노드는 표에 넣지 않았습니다. 엔진이 표를 찾기 전에 이런 수를 직접 찾습니다. 같은 국면이 여러 증명에 있으면 하나만 남겼습니다(218,396개). 그중 3,631개는 증명마다 고른 승리수가 달랐는데, 어느 쪽이든 검증된 승리수입니다.

**`lines/<id>.json`:** `{ start, history, to_move, answer?, replies: [ { words, answer: {word, how, alts}, end?, note?, replies? } ], proof }`. `words`는 결과가 같은 상대 단어 묶음입니다.
