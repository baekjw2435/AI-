# 전략 재생 실험 1 (2026-11-12): 검증 완료까지 실제로 빨라지는가

이미 푼 음절의 증명서를 '단어 하나 빠진 국면'에 따라가 보고, 막힌 곳만 다시 푸는 방법을 조정용 첫 수 28개에서 시험했습니다.
방법과 정확성 설명은 `guopsaem_root/solver_v5/experiments/replay/README_KO.md`에 있습니다.

## 결론

- **재생으로 28개 중 26개를 확정했습니다.** 모두 새 국면의 v4 증명서를 만들어 C++ `verify_v4`의 수락 조건을 통과했습니다. 2개(순발력, 행정구역)는 600초 안에 못 풀어 미확정입니다.
- **새로 확정된 첫 수는 23개입니다.** 지는 수 22개, 이기는 수 1개(권력·권역)입니다. 직접 탐색 600초로는 못 푼 준결승·급상승·낙승도 들어 있습니다.
- **실제 시간은 탐색 국면 수만큼 줄지 않습니다.** 재생 뒤에는 증명서 쓰기와 검증이 거의 전부입니다.
  - 쉬운 음절(급·흥·엽·율) 10개: 검증까지 1.6~2.8배 빨랐습니다.
  - 어려운 음절(역·승): 원본 증명이 준비돼 있으면 교역은 569초 → 82초(7배)였고, 준결승·급상승·낙승은 직접 탐색 600초에 미확정, 재생은 164~176초에 확정이었습니다.
- **원본 증명을 한 번만 쓰면 이득이 없거나 작습니다.** 준비 비용이 직접 푸는 것과 비슷하기 때문입니다. 이득은 원본 하나를 여러 첫 수에 다시 쓸 때 생깁니다.
- **잘 안 되는 경우가 있습니다.** 판정이 예측과 반대인 권력은 재생이 직접 탐색보다 조금 느렸습니다. 짝 종류인 순발력·행정구역은 막힌 곳이 1만 곳을 넘었고 끝내 못 풀었습니다.

## 조건

- 대상: 조정용 음절의 첫 수만 골랐습니다. 넘겨주는 음절이 급·흥·엽·율·역·승인 것 전부입니다(`../../replay1_cases*.json`).
- 국면: 시작 음절을 받고 첫 단어를 낸 직후(상대 차례).
- 한 실행에 코어 하나, 저장표 1GB. 시간 한도는 쉬운 음절 120초, 어려운 음절 600초입니다. 한도에는 재생 시간이 들어갑니다.
- 막힌 곳 탐색 예산: 국면마다 20만 국면.
- 직접 탐색은 쉬운 음절 10개 전부와, 어려운 음절에서는 미리 정한 규칙(목록의 앞 3개씩: h01~h03, s01~s03)으로 6개만 돌렸습니다.
- '전체' 시간 = 계산기 프로세스의 실제 시간(저장표 준비, 원본 읽기, 재생, 탐색, 증명서 쓰기) + 검증기의 실행 시간.
- 계산기는 동시에 3개까지 돌리는 것이 원칙인데, 뒤쪽에는 4개가 돈 구간이 있습니다. 어려운 음절의 직접 탐색 6개 모두와 재생 실행 4개(h10, h11, s06, s07)가 그 구간에 걸쳤습니다. 그 실행들은 조금 느렸을 수 있습니다.

## 못 푼 것과 잘 안 된 것

- **순발력, 행정구역 (미확정).** 둘 다 '짝' 종류입니다. 시작 국면에서는 왕복 짝으로 지워지던 수가, 첫 수를 둔 뒤에는 되살아납니다.
  - 순발력: 막힌 곳 14,722곳 중 9,064곳이 '옛 마디에 없던 새 수'였습니다. 막힌 곳 탐색 14,497번 중 164번이 예산 안에 안 풀렸고, 남은 탐색 493초로도 결론이 나지 않았습니다.
  - 행정구역: 막힌 곳 11,652곳 중 11,203곳이 새 수였습니다. 84번이 안 풀렸습니다.
  - **보강 시도:** 막힌 국면의 음절 증명서(순 또는 행, 역)를 함께 주는 옵션(`--replay-lib`)을 만들어 한 번씩 돌렸습니다. 새 수의 대부분은 그 증명서로 풀렸지만(순발력 9,369번 중 9,326번), 남은 것 때문에 600초 안에 결론이 나지 않았습니다. 이 두 사례에서는 효과가 없었습니다(`extra/h01_lib.json`, `extra/h11_lib.json`).
  - 같은 짝 종류인 급상승·낙승·학력은 재생으로 확정됐습니다. 짝이라고 다 막히는 것은 아닙니다.
- **권력 (이기는 수).** 넘겨준 역은 '받으면 승'이라 예측은 지는 수였습니다. 실제는 이기는 수라서 옛 전략이 통하지 않았고, 재생(61.7초)이 직접 탐색(53.3초)보다 조금 느렸습니다.
- **역전승.** 재생만으로는 뿌리가 증명되지 않아 남은 탐색에 375초가 들었습니다. 그래도 확정됐습니다.

  - 올린 브랜치를 새로 내려받아 파일 20개와 원본 8개의 sha256이 기록과 같은 것을 확인했습니다.
  - 다시 확인하는 법: `python3 replay_archive.py replay1 --recheck 1`
- 완급·직급·학급의 재생 증명서는 급의 원본 증명서와 바이트까지 같습니다. v4 증명서에는 수만 적혀 있어서, 같은 파일이 여러 국면에서 통과할 수 있습니다. 검증은 국면마다 따로 했습니다.
