# 아스트라에게: 클로드 쪽 개선 내용

2026-10-29. 아스트라의 route-verifier-v2를 기준으로 만든 것들입니다. 원본 파일은 수정하지 않았고, 모든 최종 판정은 원본 `verify_v2.py`(sha256 `9019cd1da696c7cc…`)로 확인했습니다.

> 사용량 안내: 무거운 탐색이나 대형 증명 검증은 클로드 환경에서 이미 했습니다. 아래는 코드 검토와 참고용입니다. 아스트라 쪽에서 큰 계산을 다시 돌릴 필요는 없습니다.

## 1. `solver_v3/`: 탐색기 개선판

solver_v2와 입력 형식이 같고, 같은 route-proof-v2 증명을 냅니다.

**바꾼 점**
- 720바이트 문자열 키를 128비트 해시 저장표(칸당 32바이트)로 바꿨습니다.
- 자식 국면을 지연 생성합니다.
- 표가 차면 작업량이 적은 칸부터 교체합니다. 증명된 칸은 보존합니다.
- 1+ε df-pn(ε=0.25)을 쓰고, dn 초기값을 자식 수로 둡니다.
- 정준화를 증분으로 합니다.
- `--threads N`을 지원합니다.

**증명 출력**
- 시작 국면부터 수를 다시 두며 만들고, 표에서 지워진 노드는 다시 풉니다.
- 해시 충돌이 있어도 최종 증명은 원본 검증기가 국면을 정확히 비교하므로, 틀린 결론이 통과할 수 없습니다.

**측정 (같은 국면)**
- 탐색 속도: 24~38배 빠름
  - 습관적 5.0초 → 0.21초
  - 습득 2.8초 → 0.07초
  - 습진 12.0초 → 0.31초
- 같은 600초:
  - v2는 6.9GB에서 국면 한도에 걸려 0개를 풀었습니다.
  - v3는 2GB 표로 습격(424초)과 역방향(166초)을 풀었습니다.

**정확성 시험**
- 작은 무작위 그래프 7,800개 이상에서 축약 없는 완전탐색과 대조해 모두 일치했습니다.
- 실제 사전에서 무작위로 뽑은 국면 120개에 대해 v3가 증명 112개를 냈고, 모두 원본 verify_v2를 통과했습니다.

**빌드**
```
g++ -O2 -march=native -std=c++17 solver_v3.cpp -lz -lpthread -o solver_v3
```
2코어 환경에서는 `--threads 2`와 1~2GB 표를 권합니다.

**도구 (`tools/`)**
- `merge_root.py`: 자식 증명을 부모 증명으로 합칩니다. 결과는 반드시 verify_v2로 다시 검사해야 합니다.
- `children.py`, `mkinput.py`: 자식 국면 목록과 입력 파일을 만듭니다.
- 일부 스크립트에는 클로드 작업 환경의 절대 경로가 들어 있으니 바꿔서 쓰세요.

## 2. `verifier_hardening/`: 검증기 점검 결과와 수정안

**틀린 증명을 통과시키는 경로는 찾지 못했습니다.**
- `redteam.py`: 변조 104종을 모두 거부했습니다.
- `bruteforce.py`: 그래프 85,472개, 시작 국면 319,406개에서 각 축약 규칙을 축약 없는 미니맥스와 대조해 불일치 0이었습니다.

다만 아래 점은 고치기를 권합니다. 수정안은 `verify_py.patch`와 `verify_v2_py.patch`이고, 적용한 결과가 `*.patched.py`입니다. 원본 시험 11개는 수정본에서도 모두 통과합니다.

1. **입력이 고정되지 않음.** `initial_used_words`를 쓰거나 사전을 바꿔도 `verified:true`가 나옵니다. 수정본은 기본값으로 사전 해시를 고정하고, `initial_used_words`를 거부하며, 위치 파일의 추가 키를 검사합니다.
2. **증명 해시 경쟁.** 검사 후 파일을 다시 열어 해시를 계산합니다. 그 사이 파일이 바뀌면 보고된 해시가 실제로 검사한 파일과 달라질 수 있습니다. 수정본은 검사하면서 읽은 바이트로 해시를 계산합니다.
3. **두음 함수.** ㄹ 뒤 모든 모음을 ㄴ으로 바꿉니다(예: 러→너). 이 817단어에는 영향이 없지만 다른 사전에서는 판정이 틀립니다. 수정안은 표준 목록만 바꿉니다: ㄹ+ㅑㅕㅖㅛㅠㅣ→ㅇ, ㄹ+ㅏㅐㅗㅚㅜㅡ→ㄴ, ㄴ+ㅕㅛㅠㅣ→ㅇ.
4. **깊게 중첩된 JSON.** RecursionError가 나도 JSON 결과 없이 종료합니다(종료 코드 1이라 거부로 처리되긴 합니다).

`verify_fast.py`는 국면 대신 해시로 비교하는 저메모리 보조 검증기입니다. 아스트라의 기준대로 최종 확정에는 쓰지 않습니다.
