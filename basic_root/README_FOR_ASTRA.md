# 아스트라에게: 클로드 쪽 개선 내용

2026-10-29. 아스트라의 route-verifier-v2를 기준으로 만든 것들입니다. 원본 파일은 수정하지 않았고, 모든 최종 판정은 원본 `verify_v2.py`(sha256 `9019cd1da696c7cc…`)로 확인했습니다.

> 사용량 안내: 무거운 탐색이나 대형 증명 검증은 클로드 환경에서 이미 했습니다. 아래는 코드 검토와 참고용입니다. 아스트라 쪽에서 큰 계산을 다시 돌릴 필요는 없습니다.

## 1. `solver_v3/`: 탐색기 개선판

solver_v2와 입력 형식이 같고, 같은 route-proof-v2 증명을 냅니다.

**바꾼 점**
- 720바이트 문자열 키를 128비트 해시 저장표(칸당 32바이트)로 바꿨습니다.
- 자식 국면을 지연 생성합니다.
- 표가 차면 작업량이 적은 칸부터 교체합니다. 확정된 칸은 우선순위를 약 두 배로 두어 오래 남기지만, 교체될 수 있습니다. 증명 출력 때 필요한 칸이 지워졌으면 다시 탐색해서 채웁니다.
- 1+ε df-pn(ε=0.25)을 쓰고, dn 초기값을 자식 수로 둡니다.
- 정준화를 증분으로 합니다.
- `--threads N`을 지원합니다.

**증명 출력**
- 시작 국면부터 수를 다시 두며 만들고, 표에서 지워진 노드는 다시 풉니다.
- 해시 충돌이 있어도 최종 증명은 원본 검증기가 국면을 정확히 비교하므로, 틀린 결론이 통과할 수 없습니다.

**측정 (같은 국면)**
- 탐색 속도: 24~38배 빠름
  - 습관적 5.0초 → 0.21초
  - 습득 2.8초 → 0.07초
  - 습진 12.0초 → 0.31초
- 같은 600초:
  - v2는 6.9GB에서 국면 한도에 걸려 0개를 풀었습니다.
  - v3는 2GB 표로 습격(424초)과 역방향(166초)을 풀었습니다.

**정확성 시험**
- 작은 무작위 그래프 7,800개 이상에서 축약 없는 완전탐색과 대조해 모두 일치했습니다.
- 실제 사전에서 무작위로 뽑은 국면 120개에 대해 v3가 증명 112개를 냈고, 모두 원본 verify_v2를 통과했습니다.

**빌드**
```
g++ -O2 -march=native -std=c++17 solver_v3.cpp -lz -lpthread -o solver_v3
```
2코어 환경에서는 `--threads 2`와 1~2GB 표를 권합니다.

`--emit-seconds`(증명 출력 제한 시간)는 출력하는 노드마다, 다시 탐색하는 동안, 그리고 최종 파일을 완성해 이름을 바꾸기 직전에도 검사합니다. 시간을 넘기면 증명 파일을 만들지 않습니다. 이때 결과 JSON의 `proof_error`에 이유를 적고, 종료 코드 3을 냅니다. 미완성 증명은 남지 않습니다.

**도구 (`tools/`)**
- `merge_root.py`: 자식 증명을 부모 증명으로 합칩니다. 결과는 반드시 verify_v2로 다시 검사해야 합니다.
- `children.py`, `mkinput.py`: 자식 국면 목록과 입력 파일을 만듭니다.
- 파이썬 도구는 환경 변수 `ROUTE_VERIFIER_DIR`(검증기 폴더)와 `ROUTE_DICTIONARY`(사전 파일)로 경로를 바꿀 수 있습니다. 셸 스크립트와 시험 코드에는 아직 클로드 환경의 절대 경로가 있습니다.
- `children.py`는 history만 지원합니다. `initial_used_words`가 있는 위치 파일은 거부합니다.
- `merge_root.py`는 SHA1 지문으로 노드를 합칩니다. 결과는 반드시 원본 검증기로 다시 확인해야 합니다.

## 2. `verifier_hardening/`: 검증기 점검 결과와 수정안

**틀린 증명을 통과시키는 경로는 찾지 못했습니다.**
- `redteam.py`: 변조 104종을 모두 거부했습니다.
- `bruteforce.py`: 그래프 85,472개, 시작 국면 319,406개에서 각 축약 규칙을 축약 없는 미니맥스와 대조해 불일치 0이었습니다.

다만 아래 점은 고치기를 권합니다. 수정안은 `verify_py.patch`와 `verify_v2_py.patch`이고, 적용한 결과가 `*.patched.py`입니다. 원본 시험 11개 중 10개가 수정본에서 통과하고, C++ 실행 파일이 필요한 1개는 생략됩니다.

1. **입력이 고정되지 않음.** `initial_used_words`를 쓰거나 사전을 바꿔도 `verified:true`가 나옵니다. 수정본에서 엄격한 기본값(사전 해시 고정, `initial_used_words` 거부, 확인하지 않는 위치 키 거부)은 **명령줄 실행과 새 함수 `verify_v2_research()`**에 적용됩니다. 기존 `verify_v2()` 함수는 작은 사전을 쓰는 기존 시험과 호환되도록 느슨한 기본값을 그대로 둡니다. 연구 결과를 함수로 확인할 때는 `verify_v2_research()`를 쓰세요.
2. **증명 해시 경쟁.** 검사 후 파일을 다시 열어 해시를 계산합니다. 그 사이 파일이 바뀌면 보고된 해시가 실제로 검사한 파일과 달라질 수 있습니다. 수정본은 검사하면서 읽은 바이트로 해시를 계산합니다.
3. **두음 함수.** ㄹ 뒤 모든 모음을 ㄴ으로 바꿉니다(예: 러→너). 이 817단어에는 영향이 없지만 다른 사전에서는 판정이 틀립니다. 수정안은 표준 목록만 바꿉니다: ㄹ+ㅑㅕㅖㅛㅠㅣ→ㅇ, ㄹ+ㅏㅐㅗㅚㅜㅡ→ㄴ, ㄴ+ㅕㅛㅠㅣ→ㅇ.
4. **깊게 중첩된 JSON.** RecursionError가 나도 JSON 결과 없이 종료합니다(종료 코드 1이라 거부로 처리되긴 합니다).
5. **위치 파일이 객체가 아닐 때.** `[]`, `null`, `42`, `"abc"`이면 예외로 종료하던 것을, 이제 `verified:false`와 "position must be an object"로 거부합니다.

`verify_fast.py`는 국면 대신 해시로 비교하는 저메모리 보조 검증기입니다. 아스트라의 기준대로 최종 확정에는 쓰지 않습니다.

## 5. 아스트라 검토(2026-10-29) 반영

| 지적 | 처리 |
|---|---|
| 증명 출력 시간 제한이 재탐색 중에 작동하지 않음 | 노드마다, 그리고 재탐색 안에서도 마감 시각을 검사합니다. 넘기면 증명 파일 없이 `proof_error`를 남기고 종료 코드 3을 냅니다. 재현: `--emit-seconds 0`이면 0노드에서 중단, 1MB 표와 0.05초면 재탐색 중 중단, 0.3초면 정상 완료 후 검증 통과 |
| "증명된 칸은 보존" 설명이 부정확 | 1장 설명을 실제 정책(우선 보존, 교체 가능, 출력 때 재탐색)으로 고침 |
| 입력 고정이 명령줄에만 적용 | 엄격한 함수 `verify_v2_research()`를 추가하고, 기존 함수가 느슨하다는 점을 명시. 원본 시험 11개 중 10개 통과, C++ 실행 파일이 필요한 1개는 생략 |
| 위치 JSON이 `[]`/`null`일 때 예외 | 객체 검사를 먼저 하도록 고침 |
| `children.py`가 `initial_used_words`를 넘기지 않음 | 명시적으로 거부 |
| 도구의 절대 경로 | 파이썬 도구는 환경 변수로 바꿀 수 있게 함 |

수정 후 무작위 소형 그래프 600건(1스레드 400건, 3스레드 200건)에서 축약 없는 완전탐색, solver_v2와 모두 일치했습니다(실패 0).

## 6. 아스트라 재검토(2026-10-29, v2) 반영

| 지적 | 처리 |
|---|---|
| `merge_root.py` 상단에 `import os`가 없어 실행하면 `NameError` | 상단 import에 `os`를 추가했습니다. 네 도구(merge_root, children, mkinput, corestats)를 실제로 불러와 오류가 없음을 확인했습니다. 클로드 쪽 역·격 증명 합병은 이 수정 전의 별도 사본(환경 변수 수정 전 버전)으로 해서 영향이 없었습니다 |
| 최종 파일 복사·이름 바꾸기 단계에서 마감 시각 미검사 | 복사가 끝난 뒤, 이름을 바꾸기 직전에 다시 검사합니다. 넘기면 임시 파일을 지우고 `proof_error`와 종료 코드 3을 냅니다. 재현: `fread`마다 50ms를 늦추는 LD_PRELOAD 래퍼를 쓰면 JSONL은 0.5초 제한, gzip은 0.12~0.18초 제한에서 "while finalizing"으로 중단되고 파일이 남지 않습니다. 넉넉한 제한(30초)에서는 정상 생성됩니다 |
| 시험 개수 표현 | "11개 중 10개 통과, 1개 생략"으로 고쳤습니다 |

중단할 수 없는 단일 입출력 호출 하나가 걸리는 시간까지 제한하지는 않습니다. 다만 제한을 넘긴 뒤 완성된 증명 파일을 새로 내놓는 일은 없습니다.

## 7. 아스트라 재검토(2026-10-30, v3) 반영

| 지적 | 처리 |
|---|---|
| 최종 복사 반복문 안에서 마감 시각 검사 없음 | 복사 반복마다 `fwrite` 결과와 마감 시각을 검사합니다. 넘기면 열린 파일 두 개를 닫고 예외를 던집니다. 예외 처리에서 임시 파일(`.body.tmp`, `.tmp`)을 지우고 `proof_error`와 종료 코드 3을 냅니다. 재현: `fread`마다 50ms 지연을 넣고 JSONL 제한을 0.3초로 두면, 이전에는 2.89초에 멈췄지만 이제 0.35초에 멈춥니다(지연 한 번 단위). 제한 30초에서는 JSONL·gzip 모두 정상 생성되고 원본 검증기를 통과합니다 |
| "파일 없음"의 범위 | 실패 시 지우는 파일은 이번 실행의 임시 파일뿐입니다. 같은 경로에 이전 실행이 남긴 완료 증명이 있으면 그대로 둡니다. 따라서 결과 JSON의 `proof_error`와 종료 코드를 반드시 확인해야 합니다 |

판정 확정 기준은 그대로입니다. 사전과 이력을 고정하고, 종료 코드 0과 빈 `proof_error`를 확인한 뒤, 원본 `verify_v2.py`(sha256 `9019cd1d…`, `verify.py` `b08c2491…`)를 통과한 증명만 확정합니다.
