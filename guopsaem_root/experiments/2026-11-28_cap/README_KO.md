# 2026-11-28 구없샘 B 2차: 사용 횟수 상한을 탐색에 넣는 실험

아스트라 의견(11-28)에 따른 범위: 상한 구현의 정확성 대조, 그리고 17초·51초 두 판(`q40_s1` 받는 쪽 승, `q40_s2` 패)의 시간 비교.
기준: 같은 코어·메모리(저장표 1GB)·탐색 순서에서 상한만 켜고 끄고, 걸린 시간·탐색 국면 수·상한 덕분에 다른 상태의 저장 칸을 다시 쓴 횟수를 비교한다. 탐색량이 절반 이하로 줄지 않으면 B를 멈춘다(실제 시간도 함께 본다).

## 1. 규칙의 정확성 (`test_cap.py`)

- 상한: 단일 출발 고리가 아닌 묶음 g(출발 S, 도착 t), 현재 꼭짓점 c에서 uses(g) ≤ min(n_g, out(t)+1, Σ_{u∈S}(in(u)+[u=c])). 공유 묶음 포함.
- cap_normalize: normalize 뒤, 그 단계에 남은 판으로 상한을 다시 세고 normalize를 반복해 고정점까지. 정적 승패가 나오면 그 값을 돌려줌(버리지 않음).
- 줄이지 않은 묶음 게임의 완전탐색과 대조. 판 종류: 임의 그래프(공유 묶음·공유 고리·다중도 1~4), 함정 꼭짓점 그래프(나감 1~2, 들어옴이 여러 단어인 묶음), 사전 모양 판(기존 시험 생성기, 왕복 쌍 포함). 검사: 상한 한 번 적용·고정점·멱등성, 그리고 매 수마다 상한을 적용하는 탐색의 값(모든 자식 전개).
- 결과: 시드 1(200판, 5,905국면), 시드 11(1,500판, 43,273국면), 시드 23(1,500판, 43,176국면)에서 불일치 0. 상한이 정규형을 바꾼 국면 5,560개.
- 일부러 틀린 변형 3개(+1 없음, 현재 꼭짓점 항 없음, 단일 출발 고리에 적용)는 모든 시드에서 잡힘.

## 2. 계산기 실험판 (`solver_v5_cap.cpp`, 원본 solver_v5는 그대로)

- `--cap 1`: 탐색 상태·증명서·교차 검사는 그대로 두고, 저장표의 열쇠만 상한을 적용한 상태(한 번 적용)의 해시로 바꿈. 묶음별 out/in 합을 상태에 두고 수마다 고침.
- `--cap 0`은 원본과 탐색 국면 수·자식 생성 수가 똑같음(5개 판에서 확인).
- `--cap 1 --selfcheck 1`: 자식마다 처음부터 다시 만든 열쇠·합과 증분 계산을 대조, 5개 판에서 어긋남 없음.

## 3. 시간 비교 (`timing.txt`, `capstats.txt`, 단일 스레드, 저장표 1GB, 두 번씩)

| 판 | 상한 | 결과 | 시간(초) | 탐색 국면 |
|---|---|---|---:|---:|
| q40_s1 | 끔 | 받는 쪽 승 | 17.48 / 16.89 | 6,986,558 |
| q40_s1 | 켬 | 받는 쪽 승 | 25.79 / 26.35 | 7,259,303 (+3.9%) |
| q40_s2 | 끔 | 받는 쪽 패 | 50.65 / 51.94 | 16,241,536 |

- 상한 덕분에 다른 상태의 저장 칸을 다시 쓴 횟수(저장표를 찾아 맞은 것 중, 저장된 상태가 상한 전에는 다른 상태였던 것):
  - q40_s1: 1,934만 번 중 3,065번(0.02%)
  - q40_s2: 3,722만 번 중 49,040번(0.13%)
- 상태 합치기는 거의 일어나지 않았습니다. 탐색 국면 수의 차이(+3.9%, −10.8%)는 열쇠가 바뀌어 저장 칸의 자리·교체 순서가 달라진 영향으로 보입니다.
- 시간은 33~50% 늘었습니다(자식마다 상한을 다시 세는 비용).

## 4. 결론

- 규칙은 맞지만, 탐색에 넣어도 같은 상태로 합쳐지는 경우가 0.02~0.13%뿐이라 효과가 없습니다. 비용을 0으로 줄여도 탐색량 절반이라는 기준에 한참 못 미칩니다.
- 정한 기준에 따라 이 방향(B의 상한 실험)은 멈춥니다. 실험판은 채택하지 않았으므로 증명서 검증(verify_v4) 단계까지는 가지 않았습니다.
