# 수 정렬 실험: 결과 (2026-11-05)

`solver_v5_order.cpp`는 solver_v5에 특징 기반 초기 pn/dn을 더한 복사본입니다.
- `--init 5`: 2수 앞 이동 가능 수
- `--init 6`, `--init 7`: 단어 수
- `--init 8`: 학습 모델 (학습은 아직 안 함)
- `--init 9`: 강제 응수 가중

점수는 탐색 순서에만 쓰이고, 수를 버리거나 승패를 정하지 않습니다. `--init 1`은 v5와 같은 탐색입니다(탁 226,823국면으로 확인).

측정 결과(자세한 내용과 파일은 `guopsaem_root/experiments/2026-11-05/README_KO.md` 3절):

| 방식 | 817 28음절 탐색 국면 (기하평균, 기본 대비) |
|---|---:|
| 5 | 1.04 |
| 6 | 0.94 |
| 7 | 0.90 |
| 9 | **0.84** |

`--init 9`를 실제 시간까지 포함해 다시 쟀습니다(42음절, 그중 26음절은 처음 보는 음절, 국면 상한 4,000만):
- 확정은 28 → 29개로 하나 늘었습니다(웅).
- 미확정까지 포함한 작업 시간 합계는 오히려 늘었습니다. 42음절은 2,450 → 2,629초(+7.3%), 새 26음절은 2,120 → 2,354초(+11.0%)입니다.
- 두 방식이 모두 푼 음절만 보면 탐색 국면은 0.83~0.86배였지만, 시간은 −4.4%(28개)와 +0.2%(새 12개)였습니다.

결론: 같은 국면 수 한도에서 하나 더 풀었지만, 같은 시간에서의 우위는 확인되지 않았습니다. 기본 탐색 방식(`--init 1`)을 유지합니다.
