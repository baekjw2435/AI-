# verify_v3: 한쪽 방향 두음법칙용 검증기 (구없샘 루트)

원본 `verify.py`·`verify_v2.py`(817 연구)는 그대로 두고 따로 만든 검증기입니다. 다른 코드(v1·v2 검증기, 계산기)를 가져다 쓰지 않습니다.

## 왜 새로 만들었나

1. **두음법칙 표가 다름.** 단어 엔진의 표준두음법칙은 받침과 관계없이 다음만 바꿉니다.
   - ㄹ + ㅑㅕㅖㅛㅠㅣ → ㅇ
   - ㄹ + ㅏㅐㅗㅚㅜㅡ → ㄴ
   - ㄴ + ㅕㅛㅠㅣ → ㅇ

   v1·v2는 ㄹ + 나머지 모든 모음을 ㄴ으로 바꿉니다. 그래서 럼·럽·렉·렌·렘·렙·렛·뤄에서 엔진과 다릅니다. 817단어에는 이 차이가 나는 음절이 없어서 817 결과는 그대로입니다.
2. **한쪽 방향.** 락을 받으면 락·낙 단어를 다 쓸 수 있지만, 낙을 받으면 낙 단어만 씁니다. 바꾼 꼴에서 다시 바꾸지도 않습니다(려 → 여는 되지만 려 → 녀는 안 됨). v1·v2는 받은 음절을 바꾼 꼴 하나로 합치므로 락과 낙의 차이를 나타낼 수 없고, 락·랜·룸처럼 바뀌는 음절로 시작하는 단어가 있으면 사전을 거부합니다.

## 모델

- **꼭짓점**: 받은 음절 X에서 쓸 수 있는 첫 음절의 집합 {X, conv(X)} ∩ (단어 첫 음절들). 집합이 같으면 같은 꼭짓점입니다(예: 렷과 엿은 둘 다 {엿}).
- **묶음**: 출발 꼭짓점 집합(첫 음절을 쓸 수 있는 모든 꼭짓점)과 도착 꼭짓점이 같은 단어들. 출발이 둘 이상이면 **공유 묶음**입니다. 단어 하나를 여러 꼭짓점에서 쓸 수 있다는 뜻입니다(낙 단어는 {낙}과 {낙/락} 양쪽에서 씀).
- 구없샘 3,436단어: 꼭짓점 461, 묶음 2,613, 공유 묶음 55(76단어). 공유가 생기는 꼭짓점 쌍은 낙↔낙/락, 엿↔녓/엿, 눙↔눙/룽, 윤↔륜/윤, 낸↔낸/랜입니다. 이 중 {낸}은 어디서도 도달하지 않습니다.

## 정규형 (v2와 다른 곳만 굵게)

1. 짝 지우기: u→v와 v→u 묶음을 같은 수만큼 지우고, 고리는 2로 나눈 나머지만 남깁니다. **출발이 하나인 묶음끼리만** 합니다.
2. 현재 꼭짓점에서 도달 못 하는 묶음 지우기. **출발 중 하나라도 도달하면 남깁니다.**
3. 고정 라벨(최소 고정점)
   - 받는 쪽이 지는(L) 후속이 있으면 W.
   - 모든 비고리 후속이 W이면, 출발이 하나인 고리가 있을 때 W, 없을 때 L.
   - **단, 그 꼭짓점에서 쓸 수 있는 공유 고리가 남아 있으면 라벨을 붙이지 않습니다.**
4. 핵심만 남기기: 라벨 없는 꼭짓점을 거쳐 도달하는 출발이 있고, 도착에 라벨이 없는 묶음만 남깁니다.

## 왜 값이 보존되나 (검토 요청 부분)

- **짝 지우기.** 상대가 추가된 u→v를 쓰면 나는 v→u로 돌려 같은 꼭짓점·같은 차례로 돌아옵니다. 공유 묶음은 다른 꼭짓점(예: 락)에서 쓰였을 때 돌려받는 곳이 낙이 되어 원래 자리로 못 돌아오므로 짝에서 뺐습니다.
- **고정 라벨.** 라벨은 붙은 순서대로 순위를 매깁니다.
  - 이기는 쪽의 수는 순위가 엄격히 내려가는 길을 따라가므로 같은 꼭짓점을 두 번 지나지 않고, 같은 묶음도 두 번 쓰지 않습니다.
  - L 후속으로 가는 묶음은 출발하는 모든 꼭짓점이 W 라벨을 받습니다. 그래서 이기는 쪽이 쓰는 묶음은 출발이 모두 라벨 영역 안에 있고, 라벨 없는 영역에서 소모될 수 없습니다.
  - 고리 규칙은 출발이 하나인 고리(2로 나눈 나머지 1)만 씁니다. 공유 고리는 다른 꼭짓점에서 소모될 수 있고 개수 홀짝도 남아 있으므로 판정에 쓰지 않고 라벨을 미룹니다.
  - L 꼭짓점은 수가 줄어도 모든 수가 W로 가므로 그대로 L입니다.
- **핵심만 남기기.** 라벨 없는 꼭짓점의 후속에는 L이 없으므로, 라벨 영역으로 들어가는 수는 모두 지는 수입니다. 지우면 지는 수만 사라집니다.

- `test_v3_bruteforce.py`: 무작위 작은 사전 3,000개(공유 묶음 있는 것 839개), 11,422국면.
  - 단어와 규칙만으로 푼 값 = 모델(매 수 정규화)로 푼 값.

- 계산기(`solver_v4`) 쪽 시험은 `../solver_v4/tests/random_test.py`. 증명이 verify_v3를 통과하고 완전 탐색 값과 같은지 봅니다.

## 사용

```sh
python3 verify_v3.py --dictionary words_3436.txt --expected-word-count 3436 \
  --position POS.json --proof PROOF.jsonl.gz --input IN.txt
```

POS.json은 v2와 같습니다(`{"initial_syllable": "락", "history": []}`). 종료 코드 0, `verified: true`, 결과 일치를 확인합니다.
