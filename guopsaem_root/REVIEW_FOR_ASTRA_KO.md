## 1. 대상과 규칙

- 사전: 사용자가 준 목록 3개를 합친 3,436단어 `words_3436.txt` (원본 `source/`, 합치기 `tools/merge.py`).
- 대상 음절: 470개 `syllables_470.txt` (서로 다른 국면은 459개).
- 규칙: 표준두음법칙(엔진 표). 받침과 관계없이 ㄹ+ㅑㅕㅖㅛㅠㅣ→ㅇ, ㄹ+ㅏㅐㅗㅚㅜㅡ→ㄴ, ㄴ+ㅕㅛㅠㅣ→ㅇ. **한쪽 방향·한 단계**입니다. 락을 받으면 락·낙 단어를 다 쓰고, 낙을 받으면 낙 단어만 씁니다(려→녀→여처럼 이어서 바꾸지 않음). 한 경기 안 재사용 금지, 낼 단어가 없으면 패배, 첫 제시 기준.
- 원본 검증기 v2와 다른 점: v2는 ㄹ+나머지 모든 모음을 ㄴ으로 바꾸고(럼·렌·렉·렛·뤄 등에서 엔진과 다름), 한쪽 방향을 표현하지 못합니다. 817단어에는 차이 나는 음절이 없어서 817 결과는 그대로입니다.
- 사용자 목록("그 음절을 받았을 때 낼 수 있는 단어")으로 만든 판과 v3 모델은 받을 수 있는 471음절 모두에서 낼 수 있는 단어 집합이 같습니다(코드로 대조).

## 2. 모델 v3 (`verifier_v3/verify_v3.py`, 설명 `verifier_v3/README_KO.md`)

- 꼭짓점 = 받은 음절에서 쓸 수 있는 첫 음절 집합(같은 집합이면 같은 꼭짓점).
- 묶음 = (출발 꼭짓점 집합, 도착 꼭짓점)이 같은 단어들. 출발이 둘 이상이면 **공유 묶음**(한 단어를 여러 꼭짓점에서 씀). 3,436단어 → 꼭짓점 461, 묶음 2,613, 공유 묶음 55(76단어, 낙 37·윤 26·엿 9·눙 2·낸 2).
- 정규형(값 보존 근거는 README_KO.md "왜 값이 보존되나"):
  1. 왕복 쌍 지우기·고리 짝수 지우기는 **출발이 하나인 묶음끼리만**.
  2. 출발 중 하나라도 도달 가능하면 묶음을 남김.
  3. 고정 라벨: L 후속이 있으면 W. 모든 비고리 후속이 W이면 단일 출발 고리 유무로 판정. 단, **공유 고리가 남아 있으면 라벨을 붙이지 않음**.
  4. 라벨 없는 꼭짓점을 거쳐 도달하는 출발이 있고 도착에 라벨이 없는 묶음만 남김.

## 4. 증명 v4 (`verifier_v4/`, 형식 `FORMAT.md`, 설명 `README_KO.md`)

- 국면 상태를 적지 않고 `{"id","r","m":[[묶음, 자식 id]...]}`만 적습니다. 검증기가 요청 국면에서 수를 따라 두며 모든 상태를 다시 만듭니다.
- 같은 노드에 다시 도착하면 다시 만든 상태가 **바이트 단위로 같아야** 합니다. 상태는 루트 상태를 사전으로 쓴 deflate로 메모리에 보관하고, 해시만 비교하는 모드는 선택입니다.
- v3의 검사는 모두 유지했습니다.
- 검증기 두 개:
  - `verify_v4.py`: ModelV3를 import.
  - `verify_v4.cpp`: 계산기 코드를 쓰지 않고 명세에서 따로 작성. 자체 UTF-8·JSON·SHA-256·gzip 처리.
- 계산기 패치 `solver_proof_v4.patch`: `--proof-format v4` 추가, 기본은 v3.
- 시험:
  - 무작위 550사전: v3 증명은 verify_v3, v4 증명은 두 검증기로 확인. 모두 통과하고 완전 탐색과 일치.
  - 실제 23국면: 세 검증기 일치.
  - 망가뜨린 증명 40종 × 2(W 루트·L 루트): 두 검증기 모두 거부.
  - 실제 사전 385,281국면 증명:
    - 크기: gzip 기준 v3 27.7MB → v4 2.9MB (압축 전 2.04GB → 16.2MB).
    - 검증 시간: verify_v3 483초, verify_v4.py 496초, C++ 25초.
- 공격 시험(`attacks/`, 작업자가 사용량 한도로 중간에 멈춤):
  - 겨냥한 공격 118건 중 틀린 증명이 통과한 경우는 0건이었습니다.
  - 파일 형식 엄격도 차이 7건(gzip 뒤 0바이트, gzip 헤더 CRC, 입력 숫자 앞 0, UTF-16 위치 파일, 아주 깊은 JSON 중첩)은 Python이 더 느슨했습니다. 증명 내용에는 영향이 없습니다.
  - 무작위 변형(fuzz)은 하지 못했습니다.
