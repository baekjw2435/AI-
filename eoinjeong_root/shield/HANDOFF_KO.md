## 2. 보호막 규칙 (사용자 확인 완료)

1. 단어 w는 **지금 보호막 ≤ (w의 끝 음절로 이을 수 있는 단어 수)** 일 때만 낼 수 있다.
   - 이을 수 있는 단어 수 = **전체 사전 기준 고정값**, 그 음절 또는 **두음 음절**로 시작하는 단어 수 (`syllable_shield_table.tsv`).
   - 한방(이을 단어 0개)은 보호막 0에서만. 예: ~듯(듯이 1개)은 보호막 1 이하, ~션(3개)은 3 이하, ~컹(컹컹 1개)은 1 이하.
2. 보호막은 **단어 하나 낼 때마다 1씩** 준다(양쪽 합쳐서). 예: 기차12 → 차도11. "보호막 s에서 ~X 제시" = 상대가 보호막 s-1에서 X를 받음.
3. 단어는 있는데 보호막 때문에 하나도 못 내면 **진다**. (실제 경기 중간에는 생기지 않음 — 사전 전체 확인. 시작 음절이 컹·쫙·퉤 같은 드문 음절일 때만.)
4. 게임은 **보호막 12에서 시작**해 내려간다. 계산기는 0~12만.
5. 공격 목록의 '깊이'는 무시, 깊이 1(한방)만 의미 있음. 공격 목록은 **계산에 쓰지 않고 검증 대조용**.
6. **"보호막 N에서 ~X 제시"를 물었는데 X로 이을 단어 수 < N이면 승패가 아니라 "제시할 수 없음"** (예전에 이걸 '승'으로 잘못 보고한 적 있음).

## 3. 원칙 (처음부터 지켜 온 것)

- **확정 = 검증기 통과**한 것만. 통과 못 하면 '미확정'. 루트 자리(쓴 루트 단어가 있을 때)는 solver_v5 증명서를 **verify_v4가 수락 조건 8개로 수락**해야 확정.
- **시간 한도는 정한 만큼만**, 스스로 늘리지 않는다. 기본: 질문 하나 30분. 안 끝나면 **사용자에게 묻고** 4코어로 나눠 묶음마다 6시간(사용자가 "이어서 해"라고 한 경우).
- **증명서는 저장소에 보관**(큰 것은 40MB 조각 + MANIFEST), 올린 뒤 **GitHub에서 다시 받아 해시 확인**.
- 다른 연구 폴더(`basic_root/`, `guopsaem_root/`)와 **이미 확정된 결과 파일은 고치지 않는다**. 새 결과는 새 폴더에.
- 수순 지도 사이트는 공개하지 않는다.

## 4. 도구

| 파일 | 하는 일 |
|---|---|
| `shield_calc.py` | 계산기(화면 출력·증명서). 기본 C 엔진, `--engine py`는 대조용 |
| `engine/shield_engine.c` | C 엔진(탐색·보호막 0 증분 재판정·루트전·순환 음절). 처음 쓸 때 `bin/`에 자동 컴파일 |
| `shield_export.py` | C 엔진용 모형 파일(`bin/engine_model_*.txt`) 만들기(자동) |
| `shield_verify.py` | 검증기(계산기 코드 안 씀). `.json`·`.json.gz` 모두 읽음 |
| `route_proof.py` | 쓴 루트 단어가 있는 루트 자리 → solver_v5 증명서 + verify_v4 확인(`bin/`에 자동 컴파일) |
| `shield_split.py` | 큰 질문을 첫 자리의 수별로 나눠 여러 코어에서(start/status/rebalance/finish/store) |
| `shield_core.py` | 사전 그래프, 보호막 0 판정(ModelV3 정리) |

필요한 것: python3, gcc, g++, zlib (자동 컴파일). 메모리 16GB·4코어 기준으로 맞춰 둠.

### 작은 질문 (30분 안)

```
python3 eoinjeong_root/shield/shield_calc.py present 법 --shield 7 --cert 법7.json
python3 eoinjeong_root/shield/shield_verify.py 법7.json          # verified: true 여야 확정
```
- `receive X --shield N`: X를 받았을 때. `--used 단어,단어`: 이미 쓴 단어. `--all`: 이기는 수를 찾은 뒤에도 모든 수 분류(느림).
- 이기는 쪽은 이기는 수 하나로 확정되므로 기본은 찾은 하나만 보여 줌("패배 요인이 하나라도 나오면 결과 확정").
- 한 음절 보호막 1~12 한꺼번에: 4개씩 동시에(`xargs -P 4`), 질문마다 30분.

### 큰 질문 (30분 안에 안 끝날 때)

```
D=작업폴더/split_법11
python3 eoinjeong_root/shield/shield_split.py start present 법 --shield 11 --dir $D --parts 4 --hours 6
python3 eoinjeong_root/shield/shield_split.py status --dir $D        # 1분마다 확인. 받은 쪽 이기는 수가 나오면 나머지를 멈춤
python3 eoinjeong_root/shield/shield_split.py rebalance --dir $D     # 묶음이 먼저 끝나 코어가 놀면(겹치지 않게 나눠 줌)
python3 eoinjeong_root/shield/shield_split.py finish --dir $D --cert $D.json     # 다 끝났거나 이기는 수가 나왔을 때
python3 eoinjeong_root/shield/shield_verify.py $D.json > $D.ver.json            # 큰 것은 1시간·메모리 4~5GB
python3 eoinjeong_root/shield/shield_split.py store --cert $D.json --verify-json $D.ver.json \
    --out eoinjeong_root/shield/examples/beop/present_법_11 --name present_법_11 --question "보호막 11에서 ~법 제시"
```
- 수 하나 끝날 때마다 `$D/moves/move_<i>.json`에 남음. 다시 start하면 끝난 수는 건너뜀.
- `start`는 detached(setsid)로 띄우므로 세션 2시간 제한과 무관. 한도는 묶음마다 `timeout`.

## 5. 주의할 점 (겪은 문제)

- **메모리 부족**: 큰 질문 두 개를 동시에 4묶음씩(8개) 돌리다 메모리가 모자라 프로그램이 강제로 꺼진 적 있음. **엔진은 동시에 4개까지.**
- **겹친 묶음**: 손으로 나눠 주다 같은 수를 두 묶음이 따진 적 있음 → `rebalance` 명령은 겹치지 않게 만들어 둠.
- 검증기가 대조 못 하는 잎이 나오면(예: 공격 목록에 없는 이기는 수) 검증기를 고치되, **계산기 코드를 쓰지 않는다**는 원칙은 지킨다. 지금 검증기는 공격 목록 → 확정 루트 → 제자리·되돌림 단어 → 모든 단어를 짧게 두어 보기 순으로 증명.
- 증명서 크기: 보호막 11~12는 근거 자리가 100만~250만 개(압축 30~80MB) → `store`로 조각 보관.
- 사전이 바뀌면(낱말집 실시간 편집): 결과마다 사전 판을 적고, 새 판이 오면 저장된 증명서를 새 사전으로 **다시 검증**해서 불통과만 다시 계산하는 방식으로 하기로 함(도구는 아직 안 만듦 — 사용자가 Eruda로 낱말집 데이터를 모으는 방법을 상의 중).

## 7. 앞말잇기 (다른 방에서 할 때)

규칙(사용자 확인, 2026-11-27)
- 다음 단어는 **앞 단어의 첫 음절로 끝나야** 한다. 두음은 **표준 두음법칙**: 앞 단어가 '라'로 시작하면 '라' 또는 '나'로 끝나는 단어 가능
  (라디오 → 옳다구나 가능). '자'는 두음 변화가 없어 '자'로 끝나는 단어만(자수 → 여자 가능, 녀자는 사전에 없는 말).
- 보호막 규칙은 똑같다. 한도 = 그 음절(두음 포함)로 **끝나는** 단어 수.
- 루트 단어·공격 목록은 사용자가 그 방에 따로 준다(끝말잇기의 621단어·공격 목록과 다름).

푸는 방법
- **모든 단어를 거꾸로 뒤집으면 앞말잇기 = 끝말잇기**(같은 `verify_v3.conv` 두음 함수). 사전·루트 단어·공격 단어를 모두 뒤집어
  넣으면 지금 도구(ModelV3, solver_v5, verify_v4, 보호막 계산기·검증기)를 그대로 쓸 수 있다. 출력할 때만 단어를 다시 뒤집는다.
- **solver_v5·verify_v4·ModelV3는 코드를 고치지 않고 그대로 쓴다.** 루트 단어 목록을 뒤집은 파일을 사전으로 넘기면 된다.
  예: 라디오 → 옳다구나(앞말잇기)는 뒤집으면 오디라 → 나구다옳(끝말잇기: '라'를 받고 두음 '나'로 시작). 두음 방향도 같아서
  같은 conv로 맞는다. 증명서는 '뒤집은 사전의 끝말잇기'에 대한 것이고 앞말잇기와 정확히 같은 게임이다.
  verify_v4의 수락 조건 8개(사전·자리·입력·증명서 해시 포함)도 뒤집은 사전 파일 기준으로 그대로 확인한다.
- 순서: ① 앞말잇기 루트부터 확정(처음 연구처럼 루트 음절마다 solver_v5 증명서 + verify_v4 수락, `site/data.json`에 해당하는
  루트 결과 만들기) → ② 보호막 계산.
- 참고(어림): 두음 없이 뒤집은 사전으로 보호막 0 판정을 해 보면, 앞말잇기에서 안 정해지는 음절이 73개
  (객 겟 곁 굉 궐 긴 깍 꺼 꺽 꾹 꿩 끽 낮 넌 넘 넛 넥 눌 능 덜 …). 같은 방식으로 끝말잇기는 29개.
- 지금 보호막 도구는 끝말잇기 파일에 묶여 있다(`source/표준사전_어인정_전체단어.txt`, `words_621.txt`,
  `site/data.json`, `source/공격단어_목록.txt`). 앞말잇기는 이 네 가지를 앞말잇기용(뒤집은 것)으로 바꿔 끼우는 선택지를
  넣어야 한다(아직 안 만듦). 끝말잇기 결과(`examples/`)와 섞이지 않게 새 폴더(예: `eoinjeong_root/shield_front/`)에서.
